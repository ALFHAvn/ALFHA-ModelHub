# ALFHA ModelHub v0.4.0 release candidate

ModelHub now starts and stops from Windows Explorer, serves the browser
workspace from the same local address as the API, and supports
evidence-based routing between two installed Ollama models.

- **Windows launcher**. Start the application and its PostgreSQL container
  with `Start-ModelHub.cmd`. The launcher checks readiness before opening
  the browser. `Stop-ModelHub.cmd` preserves the database volume and leaves
  Ollama and unrelated containers running. [Windows setup](../README.md#local-web-ui-on-windows-11)
- **Proposal & Review**. Choose a proposer and reviewer and inspect the
  response, timing, and errors for each step. The initial proposal remains
  available when the review fails. [Workflow guide](../README.md#two-model-proposal-and-review)
- **Coding Cohorts**. Discover compatible saved reports and inspect aggregate
  results, a filterable timeline, original responses, retries, and grader
  cases. [Coding cohort guide](benchmarks.md#inspect-saved-execution-evidence)
- **Routing Preview and local dispatch**. Inspect recommendations, exclusions,
  and candidate metrics. The explicit **Generate locally** action uses a
  local-only endpoint and returns the decision with the execution result.
  [Two-model routing setup](routing-design.md#two-model-ollama-routing)
- **Structured output and Java grading**. Opt-in JSON contracts and versioned
  Java format checks report format failures separately from provider failures
  and correctness. [Structured-output evidence](structured-output-reliability.md)

## Live routing verification

Three sequential, unpaced Basics v2 reports covered all 10 tasks for each
model. All 60 executions succeeded at the provider level and matched saved
history. Ollama 0.40.16 and both model digests were stable during collection.

| Ollama model | Correct | Provider success | Median benchmark latency |
| --- | ---: | ---: | ---: |
| `qwen3:4b` | 30/30 | 30/30 | 15,051.5 ms |
| `qwen2.5-coder:3b-instruct-q4_K_M` | 15/30 | 30/30 | 8,051.5 ms |

Preview accepted all three reports and selected `qwen3:4b` with
`EVIDENCE_SELECTED` and `CORRECTNESS_BAND_THEN_LATENCY`. The 3B model fell
outside the five-percentage-point correctness band. One live routed request
returned `37` in 12,065 ms and matched its PostgreSQL history entry.
[Verification record](routing-design.md#live-two-model-verification-on-11-november-2026)
· [Archived evidence](../benchmarks/evidence/local-routing-2026-11-11/verified.json)

The measurements cover one host and 10 fixed tasks. The policy requires
matching reports in the active PostgreSQL database, an evidence cutoff,
and report completion within the last 14 days. The archive records the
original observations. New installations can use the primary Ollama
fallback while collecting qualifying evidence.

## Candidate review

The Maven project, frontend package and lockfile, and packaged Docker JAR
use version `0.4.0`. The Windows launcher serves the packaged UI and API
on loopback.

| Local check | Result |
| --- | --- |
| Maven verification with restricted Java grading enabled | 63 tests passed, including disposable PostgreSQL integration tests |
| `npm test` and `npm run build` | 21 tests passed and the production build completed |
| Docker build and example Compose validation | Passed using the repository build context |
| Windows launcher harness | Cold start, repeat start, readiness failures, and scoped shutdown passed. The harness captured the browser handoff. |
| Packaged Compose smoke test | Served the browser assets and passed chat, comparison, Proposal & Review, cohort read and incompatibility checks, routing preview and local dispatch, and history checks |

The packaged smoke test used an Ollama fixture and disposable PostgreSQL.
It replayed the three archived reports through the candidate's routing
policy. The Maven run retained the existing local collection artifacts.
