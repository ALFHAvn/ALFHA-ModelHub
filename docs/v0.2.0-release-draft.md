# ALFHA ModelHub v0.2.0 draft

ALFHA ModelHub adds a local browser workspace, evidence-based routing, and
engineering benchmarks that grade submitted code and SQL in isolated
containers.

- The browser workspace supports chat, model comparison, and paginated
  execution history. [Windows startup guide](../README.md#local-web-ui-on-windows-11)
- Routing can preview a model choice and optionally dispatch generation.
  Decisions use curated benchmark reports and include reasons for selection
  or fallback. Optional cloud dispatch verifies catalog pricing and sends
  zero-price limits. [Routing design](routing-design.md)
- The engineering suite covers 24 objective tasks. The Java coding pilot
  records sandbox outcomes alongside saved benchmark reports.
  [Benchmark guide](benchmarks.md)
- The offline evaluation workflow adds four held-out graders, provenance
  checks, a local collection script, and paired campaign summaries.
  [Repeatability protocol](benchmark-repeatability.md)

## Final Milestone 10 campaign

The frozen campaign completed all 24 measured calls across two collection
windows. The first ran on 7 November 2026 from 15:00:00 to 15:03:15. The
second ran on 8 November from 14:14:05 to 14:15:53. Times are Vietnam time
and span the first request start to the last saved execution in each window.
[Frozen campaign](../benchmarks/held-out/local-campaign-v1.json)

| --- | ---: | ---: |
| Successful provider calls | 12/12 | 12/12 |
| Passing raw submissions | 0/12 | 0/12 |
| Median successful generation latency | 7,932.5 ms | 8,731.5 ms |
| Successful latency range | 587–17,532 ms | 2,847–19,464 ms |
| Submissions with compilation errors | 3 | 5 |
| Submissions that hit the grader output limit | 6 | 4 |
| Submissions with SQL query errors | 3 | 3 |

Both models failed all three repetitions of each of the four tasks. All 12
pairs tied on raw correctness. The collector recorded zero provider,
operational, or tooling errors. Generation latency covers the provider call
and excludes sandbox grading.

All 24 responses contained Markdown fences. The frozen prompts required raw
Java source or SQL, and the graders received the exact saved responses. The
results measure compliance with that submission contract. The correctness
of the enclosed code remains unknown.

Both campaign validators passed on the measured reports. The split checker
verified 24 evaluation reports and six historical development reports with
114 distinct execution IDs across the two splits. The integrity audit used
only the two live journals. It matched all evaluation records to their saved
generation and history payloads, checked the submitted bytes against the
saved responses, and reproduced every evidence export from its complete
grader output. Raw submissions and the machine-readable audit remain in
`target/local-held-out-v1` and its referenced artifact directories.

## Proposed formatting diagnostic

Use the 24 saved responses for a paired offline diagnostic. Keep the frozen
raw verdict as the baseline. For a separate score, extract only a single
complete fenced block with the task's matching `java` or `sql` label.
Reject missing, mismatched, malformed, or multiple blocks as extraction
failures. Submit the exact extracted bytes to the same pinned sandbox grader
and save the extraction decision, original and extracted hashes, and both
verdicts. Report how many raw failures become passes and how many remain
failures, by model and task. Preserve the campaign reports and publish the
diagnostic as a separate result.
